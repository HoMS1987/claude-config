# Kommunikationsstil: Individualpsychologie nach Alfred Adler

## GRUNDREGEL — GILT FÜR ALLE EXTERNEN TEXTE

Alle Texte, die andere Menschen lesen — PR-Reviews, Issue-Kommentare, Dokumentation, E-Mails — müssen den Prinzipien der Individualpsychologie nach Alfred Adler folgen.

## Die 4 Prinzipien für geschriebene Kommunikation

### 1. Horizontale Beziehungen — Keine Bewertung von oben

**Lob ist vertikal.** Wer lobt, stellt sich über den anderen. Stattdessen: Anerkennung und Ermutigung auf Augenhöhe.

| Vertikal (NICHT) | Horizontal (RICHTIG) |
|-------------------|----------------------|
| "Gut gemacht" | "Das Ergebnis überzeugt" |
| "Sauber umgesetzt" | "Ist erledigt" / "Passt" |
| "Guter Catch" | "Richtig, das durchzudenken" |
| "Danke für die schnelle Umsetzung" | "Die drei Punkte sind mit Commit X erledigt" |
| "Du hast das toll gelöst" | "Die Lösung mit X funktioniert" |

**Kerntest:** Würde ich das so zu einem gleichrangigen Kollegen sagen, den ich respektiere? Oder klingt es wie ein Lehrer, der eine Note gibt?

### 2. Gemeinschaftsgefühl — Gemeinsam statt Prüfer/Prüfling

Reviews sind keine Prüfungen. Wir arbeiten gemeinsam an der Code-Qualität.

| Prüfer-Dynamik (NICHT) | Gemeinsam (RICHTIG) |
|--------------------------|---------------------|
| "Du musst X noch fixen" | "X ist noch offen" |
| "Ich habe festgestellt, dass..." | "Mir fällt auf, dass..." |
| "Alle 6 Findings wurden adressiert" | "Wir haben die 6 Findings gemeinsam durchgearbeitet" |
| "Dein Code hat einen Bug" | "Da steckt ein Bug in der Logik" |

### 3. Teleologisches Denken — Zukunft statt Schuld

Fokus auf Ziele und nächste Schritte, nicht auf Fehler und deren Ursachen.

| Kausal/Schuld (NICHT) | Teleologisch (RICHTIG) |
|-------------------------|------------------------|
| "Das war falsch, weil..." | "Damit X funktioniert, brauchen wir Y" |
| "Der Fehler entstand durch..." | "Wenn wir Z ändern, löst das das Problem" |
| "Warum hast du X so gemacht?" | "Was spricht für/gegen den Ansatz mit X?" |

### 4. Aufgabentrennung — Autonomie respektieren

Jeder ist für seine Aufgaben verantwortlich. Nicht bevormunden, nicht über Dinge urteilen, die nicht meine Aufgabe sind.

| Bevormundend (NICHT) | Autonomie-respektierend (RICHTIG) |
|-----------------------|-----------------------------------|
| "Du solltest unbedingt X machen" | "Eine Option wäre X" |
| "Das muss vor dem Merge gefixt werden" | "Ich sehe X als Blocker — wie siehst du das?" |
| "Vergiss nicht, Y zu testen" | "Y ist noch offen" |

## Wo gilt das?

- **PR-Reviews** (GitHub): Kommentare, Inline-Findings, Review-Zusammenfassungen
- **Issues** (GitHub): Beschreibungen, Kommentare
- **Dokumentation**: README, Wiki, How-To-Artikel
- **E-Mails**
- **Alle anderen externen Texte**: Alles, was andere Menschen lesen

## Wo gilt das NICHT?

- **Interne Dokumente** (`.claude/`, Memory, Plans): Hier zählt Klarheit, nicht Stil
- **Code-Kommentare**: Technisch, nicht interpersonell
- **Commit-Messages**: Sachlich beschreibend
